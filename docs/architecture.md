# 项目架构

[使用说明](usage.md) · [模板规则](../templates.md) · [实验结果](results.md)

## 三层知识和一条执行链

底层是页面状态与真实操作边；第二层是结构模板及功能卡；第三层是网站功能框架。三层解决不同问题：状态用于确认当前位置和回放，模板用于概括相似布局，框架用于给 Agent 提供整体功能提示。

```text
浏览器探索 → 页面状态与操作证据 → 模板聚类 → 功能卡 → 网站框架
                    ↓
               Jina 截图索引
                    ↓
任务 → 检索可达页面 → 选择目标 → 回放路径 → Actor 操作现场页面
                                                ↓
                                      后台描述与任务结束后的维护
```

图谱提供候选路线，不证明任务已经完成。卡片与框架也不是操作权限或评分依据；最终执行仍依赖现场观察，正式任务由外部评分器判定。

## 建图：浏览器串行，模型工作并行

一个线程操作浏览器并写图。候选排名与 Transition 描述可以在后台运行：当前配置支持两个描述线程和一个排名预取线程，最多四个描述作业等待完成。

父页面还没探索完时，可以预先为首个子页面排名。传入的父页面剩余候选是“待探索计划”，不能当成已经做过的动作。排名结果齐全后才进行全局排序、结构去重和 top-k 选择。

Jev 对每个候选分别判断探索价值和首次点击适宜性，当前显式启用的首次探索门槛为 0.8。打开表单与提交表单是不同候选；判断读取真实控件、表单和动作事实，不依赖站点名称黑名单。请求按问题数量与序列化大小分批，失败时不返回半份排名。

动作完成后先保存动作事实和真实前后快照。对于新目标，描述模型接收标出交互控件的前截图、后截图和精简动作事实，输出 `replayable`、`effect`、`uncertainties`，以及尚缺失的页面描述。已有描述的页面不重复描述；已知目标、无变化和失败动作按对应流程记录事实。

并行建图的 `construction-pending-v1` 边可以暂定用于回放。浏览器线程在动作前收取已完成判断，并在回放前检查许可。首次探索判断不能保证消除所有站点副作用，暂定回放也不等于已经确认可重放。

## 页面状态、空页面与局部等价

建图与回放共用 interaction 状态表示。URL 相同仍可能对应多个状态；不能因为地址没变就忽略表单、控件或可见内容变化。

确认空白或只有加载占位时不入图。如果截图有有效内容，或者内容证据尚不确定，但提取不到结构，则保留状态并分配独立空模板。空模板不参与普通匹配和聚类合并。

可选的 Jev 局部等价只处理有限的 query 值差异：其他身份字段与可见文本保持一致，最多两个 query 值变化，涉及控件比例不超过 10%（至少允许一个控件），才请求判断。模型输入是保存的完整页面上下文和精确差异位置，而不是只给几个脱离页面的参数名。

当前显式启用的接受阈值为 0.8。通过后，规则保存在图内，后续同范围差异可以直接复用。规则不授予探索或回放权限；实际点击使用当前 DOM 的参数。隐藏参数是否影响业务语义仍是表示边界，这套规则不能当成普遍可靠的状态等价证明。

## 检索与普通导航

Jina 索引覆盖图中所有活动节点的截图，不在编码阶段按根可达性丢弃页面。执行检索时再取以下两部分的并集：当前状态可沿允许边到达的页面，以及逻辑入口可到达的页面。当前状态无法识别时，仍保留入口可达候选。

检索先给允许候选评分，再在每个模板中只保留最高分页，最后取 top-k。没有模板归属的页面单独保留。清退分不参与检索排序。

导航优先走当前位置到目标的记录路径。当前位置无路而入口有路时，在同一会话访问入口 URL，识别实际到达的根状态，再重新求路。根页面变化会更新 `root_entry.current_state`；旧节点和快照继续保存，不把新内容覆盖到旧状态 ID。

回放使用当前控件的角色、名称和目标等事实重新定位。观察与定位共享最近 landmark 区域，必要时用区域区分同名控件。缺失、仍不唯一或状态不符时，停止剩余路径，保留现场并交给 Actor；不强制点击，不偷偷重放失败动作。

已确认的输入边允许参与路线规划，但回放停在输入前。历史输入文本不会替 Actor 填入当前任务。

## Actor 观察与上下文

执行沿用 WebNavigator 的 Agent 和动作接口。本方法保留 `single-action-v2` 单动作约束，输出采用 `compact-context-v1`：观察摘要、行动理由、单个 ACTION 和高亮编号，另有可选 NOTE。观察摘要只写动作前已看到的一两句关键事实，理由只写一句。取消每轮目标复述、约束列表、历史总结和模式分析；历史输入也不再显示模式分析。NOTE 仅保存后续需要且未在观察摘要中重复的事实。点击提交之后，必须等下一轮观察确认结果，才能用 stop 报告成功。去除了旧提示中“必须写标题”与“禁止所有标题”的冲突，以及反复出现的惩罚措辞。

高亮编号用于提取原始页面证据，通常选 1–3 个、最多 5 个，重要的放在前面。程序只接受当前展示的 AX 中的编号（包括本轮搜索已揭示的内容），去重后保留前 5 个有效编号，并记录无效、重复和超限数量；不为此重生成动作。空高亮直接使用观察摘要，非空高亮继续使用原有结构裁剪及大小限制。这个上限约束模型选中的编号数量，不等于裁剪后的树只有五个节点。原始模型响应照常保留。原版对照缺省保留原有输出和模式历史。

输入采用 `task-memory-history-v1`，由本方法的 [actor_input.py](../web2kg/stage2/actor_input.py) 生成。任务目标只展示一次；原计划树中的 NOTE 放入独立的 `TASK MEMORY` 区域，保留记录时机和原文，包括旧接口追加的失败提示。内部计划树仍供原 Agent 使用，输入不再显示它的编号、空结构和重复目标。

最近五步同时保留动作前摘要、选中证据、理由、动作及程序记录的结果。更早步骤形成动作账本：完整保留每次动作及输入参数、控件名称和结果，完全相同的 URL、摘要、证据与理由，在引用更短时改成指向首次出现步骤的引用；短句直接保留。理由若与该步摘要或证据完全相同，则不再重复。独有的理由可能包含用户名、数值或筛选条件，所以仍保留为 `intent`，导航理由中的独有信息也保留，明确它们是当时的想法，不是执行结果。不同数字、否定词或空格不会被模糊去重，也不额外调用模型判断“哪些事实可以忘掉”。因此压缩幅度取决于重复量，不能保证每轮输入都更短。

动作控件的角色和名称在旧 DOM 释放前保存。程序结果区分执行异常、浏览器命令返回和导航尝试；异常可能发生在部分操作之后，不能因此认定站点没有变化。`executed` 也只表示命令返回，不证明发帖或修改等业务成功。后续观察继续保留在相应步骤中，原始响应和轨迹不因输入投影而删除或改写。

导航历史只保留查询目标、站点、目标页、实际 URL、到达状态、具体错误及下一步限制。未选到目标不能继承上次导航成功；输入前暂停和状态失配仍明确要求现场操作。网站框架只提供概览、区域名称、通用导航提示与限制；当前功能卡保留用途、功能、条件分支和不确定性，去除清退重要性等维护字段。相同邻近目标的描述只出现一次，但各入口名称和当前控件编号都保留。页面选择器继续使用原框架投影；原版 WebNavigator 的输入不采用这些规则。

当执行配置的 `site` 为 `reddit` 时，本方法给 Actor 和页面选择器附加一句环境说明：本基准的 Reddit 就是当前 Postmill 实例，不需要前往公网 Reddit，检索未命中也不代表网站不可访问。说明按配置站点注入，不按任务文本里的关键词触发；其他站点的提示词保持不变，历史冻结实验和原版对照也不改写。

本方法的 `actor-action-v1` 将行动决策与辅助查询分开计数。一次 Actor 请求及其格式、传输重试使用同一决策编号；成功解析为可用 AX 搜索后，该编号转记为辅助查询，命中或未命中均不扣行动额度。页面选择器单列，浏览器行动轮次由环境继续计数。超过搜索上限的输出不能取得免费额度，而是走有限格式纠错。所有物理请求和用量仍逐条保存；预算耗尽的队列判定使用相同的决策计数，不能再用物理请求数推断。原版对照不传入该策略，继续使用其原有共享调用额度。

原版对照的Verified最终答案适配与上述执行提示分开。开发版`navigation_specifications/stop.txt`使用`verified-json-stop-v1`，内容与`verified_answer.STOP_SPEC`一致；`stop_instruction`识别已适配的说明，避免重复插入。新登记保留原Agent和导航，仅替换新批次中的stop说明，`run_original`通过协议中的`unified_verified_stop`使用统一说明。其余动作不变，整个回复仍为原栏目文本，不要求整个回复变成JSON。此开关本身不启用格式校验或重生成，旧协议缺省仍走旧分支。

响应在进入 Agent 动作解析前先检查单动作要求。多个 ACTION 段、同一段中的多个命令或缺少合法动作，会触发格式纠错提示，并在同一次模型调用内重生成。观察文本、截图、历史和控件编号保持不变，不执行其中任何一个候选动作，也不新增行动步。格式尝试共用一个逻辑调用额度，但每次物理请求、token 和耗时全部记录；次数达到登记上限后停止。正式任务的 stop JSON 校验仍单独保留，页面选择器不套用 Actor 格式。

`previous-response-v1` 纠错在原输入后附上最新一次失败的可见回答（assistant）和具体校验错误（user），明确说明动作未执行、相同ACTION重复也不合法、多步操作必须分轮。再次失败时替换这对消息，不累计错误回答；下一次正常决策不带这些临时消息。只发送可见回答，不把供应商的独立推理字段作为反馈。临时网络重试仍原样重发当前纠错请求。

底层解析器按完整标题行取字段，避免把 `REASON FOR ACTION` 误当成 ACTION；括号参数里的标题文字仍是输入内容。旧解析兼容中的相同动作去重仍保留，但新协议会在其之前要求唯一 ACTION。旧冻结基线不使用这套新提示词和检查。

导航站点参数也在动作分发前校验。执行适配器将当前 Actor 的可用 `domain_navigators` 名称传给响应校验器，提示词列出同一份名称。非法参数进入已有的同观察纠错流程，模型能看到失败响应和准确的允许值；不会先落入原仓库只打印控制台错误的重试循环。站点错误最多三次，且和格式错误共用原输出重生成预算。校验不猜测网址别名，不改页面选择器或原版对照。

数值观察保护让完整整数、正负数、小数、千分位、百分比和货币数值绕过父/兄弟子串去重，保留其显示符号。其他文本仍使用原规则。适配在任务开始前安装，结束时恢复，原版对照不因此改变。

启用有界 AX 搜索时，Actor 初始收到 800 行，可在同一次观察中搜索最多三次，每次窗口 800 行，合并最多 2500 行。搜索使用同一份 AX 和编号，不额外操作浏览器；模型调用仍计入额度。下一次真实动作后重新观察。未启用搜索时使用入口配置的固定截断值，不能把所有模式统称为“1000 行”。

普通 Actor 接收当前模板卡与精简邻接提示；页面选择器不接收这份当前模板块。网站框架可以提供给两者。模型上下文是投影后的提示，完整匹配分数、证据引用和原始快照仍保存在日志中。

## 执行描述为何可以放到后台

执行阶段采用 `background-compact-v1`。主线程保存动作事实和前后快照后提交描述作业，Actor 可以继续下一步；只有路线依赖、诊断依赖、队列已满或任务收尾时才等待。

短控件编号 `B1/A1` 与输出 schema 共用证据表，由程序映射回真实控件 ID。页面摘要只认领一次，历史摘要可复用；相同转换可以共享作业，失败动作不会被另一次成功的解释覆盖。

这里与建图不同：`execution-description-v2` 新边在待解释、失败或额度耗尽时都不可回放，输入边也不例外。后台模型不直接改图，完成结果由主线程批量合入，避免两个线程同时修改资产。

## 任务结束后的维护

1. 收齐后台描述，保存执行证据。
2. 超过容量时，按最短主干树的叶子进行清退。任务中的新节点和入口受保护。
3. 更新模板成员和维护计数，判断是否需要全局聚类。
4. 对确定后的图并行补截图索引和生成卡片。已有向量复用；收尾卡片最多三路，在线新卡仍同步。
5. 需要网站框架时，等待卡片完成后生成。全局分区、卡片与框架准备成功后才发布。

单卡刷新和全局聚类的门槛、失败后的计数处理见[模板规则](../templates.md)。索引与卡片的失败分别记录，一方失败不抹掉另一方已经完成的结果。正常模型失败时保留旧资产；多文件发布尚不能承诺进程崩溃时的事务原子性。

制卡请求的字段长度、列表数量和非空证据要求与后置校验保持一致。`request_card` 将业务校验交给 `ResponsesClient.json` 的验证回调；只有明确的模型输出错误进入已登记的有限重生成，其他程序或资产错误继续抛出。纠错带上最新失败的可见回答和具体错误，原代表页与图片不变；只在校验通过后将 P1 等编号映射为节点 ID。这个流程同时用于单卡小更新和全局制卡。

新快照 JSON 使用紧凑保存，图写入直接返回实际字节哈希，避免刚写完又读回。现场观察、截图和必要事实检查点仍保留。Jina 编码器一致性检查与实验输入守卫属于不同职责，不能因为减少历史扫描就取消编码器核对。

## 诊断、返回与经验

可选 `direction-confidence-v1` 在 Actor 输出中增加 `DIRECTION CONFIDENCE`，表示当前路线和拟议动作是否仍符合任务要求，不是点击成功率。未提供或非法数值记为未知，不因此拒绝一个合法动作。`confidence.py` 独立保存真实 Actor 行动计数，返回时返还预算也不减少这个计数。AX 搜索、格式纠错和回放中的多条边不重复累计。

置信度策略默认关闭。独立的低频检查在诊断本身启用时生效：连续 10 次实际行动没有完成诊断会触发检查；所有诊断仍共用原有次数上限。暂定的置信度条件为当前值不高于 0.30，或最近三个连续有效值平均低于 0.60 且至少两个低于 0.60；这些是待校准试验值。完成任意三级诊断后清空窗口，三个实际行动内不再由置信度触发，原有停滞触发不受该冷却限制。`shadow` 仅记录置信度条件；配置诊断客户端时保留原触发和十步检查，未配置时完全不诊断。`active` 必须配置诊断客户端，才可在动作执行前诊断。诊断收到的拟议动作单独标注为未执行，不能选为历史根因。若结论要求重新判断，丢弃提案后在实际现场重新生成，不写入已执行历史；物理请求和调用消耗照常保留。

诊断在无交互控件、三次到达同一状态或连续两次同动作无变化时触发。页面摘要在触发时按需整理，优先复用已有描述。缺失摘要已由后台 Transition 作业认领时，等待该作业；已有摘要则不必等待所有 Transition。诊断输入保留页面摘要与真实操作轨迹。每步 `source_page` 中将页面 `summary` 与 Actor 的动作前 `actor_observation` 放在一起；动作旁的 `transition_effect` 按本次任务的 `transition_attempt` 精确关联，并核对来源、目标和控件。同一状态多次访问时保留各步自己的 Actor 摘要，不按状态覆盖。一次导航包含多次回放时，只给起点记录附 Actor 摘要，自动回转步骤不继承该摘要。

触发诊断先收取已完成的后台描述，effect 附带完成状态、不确定性和复用标记。仍在等待、失败或没有请求解释的记录只提供状态，不套用另一次动作的 effect；仅为补齐 effect 不增加等待。Actor 摘要与 effect 明确标为模型理解，不能代替实际错误、状态变化或外部评分，也不把 highlight 加入诊断。两种文本在诊断输入中各最多 1000 字符，超过时标记截断，原始记录保留；总上下文限制不变。触发信号本身不证明偏离。

`three-tier-v1` 的模型输出使用 `verdict`：`on_track`、`uncertain` 或 `deviated`。前两级要求 `root_step=0`，程序仅通过 `diagnosis_advice` 将最新结论和建议投影到 Actor 输入，不产生返回、控件禁用或步数返还。明确偏离才接受有效历史根因步骤并进入原来的唯一一次返回流程。保存记录中的 `deviated` 布尔值由程序从结论推导，供既有审计读取，不接受旧二元响应代替新结论。后续诊断可覆盖旧建议；实际尝试返回后停止继续诊断。计数和返回动作上限不变。

确认偏离后只尝试一次返回。`return_to_observed` 优先走当前位置到目标的允许路径；无路或路径超过动作上限时，尝试从逻辑首页出发的路径。回首页使用当前会话的 URL 跳转，不重置站点，跳转本身计为一个动作。到达首页后按实际状态重新求路、重新检查剩余额度，并沿用普通导航的现场控件定位。

求路只等待可能打通目标、且长度符合剩余额度的后台 Transition；判断完成前不回放这些边。遇到输入边仍交给 Actor，实际点击或状态核验失败后不会再换路重试。返回成功还必须核验目标状态，不能仅凭到达同一个首页 URL 就认定回到了旧状态。失败也消耗这次机会，并保留禁止原控件的提示。该禁用依赖真实控件身份，而非变化的 AX 编号。

只有返回并核验成功才返还从根因轮次到触发轮次的行动预算。实际轨迹编号、请求、token 和时间都不回退。回到旧页面也不撤销之前的站点写入。

学习还需要外部成功检查，以及返回后在根因页面执行过替代操作。普通 CLI 没有独立评分时不凭 stop 自述学习。

## AgentOccam 对照

`evaluation/agentoccam.py` 在独立 worker 中加载官方 AgentOccam，避免与 WebNavigator 的同名 `browser_env` 模块冲突。保留原生 Actor、页面裁剪、历史、highlight、branch/prune 和动作处理；Qwen 通过既有传输客户端接入，浏览器关闭后交给 Verified 评分。它没有接入本方法的图谱、诊断或单动作纠错。

适配明确分为三部分：整行栏目解析与 JSON stop 提示；本地登录、网络证据采集和外部评分；两处保持观察内容的性能修复。节点复制只复制原本会保留的字段，不再先复制整棵父子树再断开连接；全文 AX 模式跳过未使用的逐节点几何预查询，真正点击时仍查询当前 DOM。原仓库文件和实验副本的差异写入材料清单。

AgentOccam 的原生序列化上限是1000行；配置中的 `max_browser_rows` 不控制这条裁剪路径。决策轮次包括 note 和规划，原生格式重生成消耗调用额度。它仍使用原生 `type` 解析：提示中的命名参数写法可能被当成正文，而 WebNavigator 已有对应的末尾参数兼容。这是当前对照的已知差异，不应把两者描述为完全相同的接口。

用户暂停后的续跑只更换调度与报告代码，已完成题引用原始目录，取消的尝试保留并单独计费。工程失败必须走独立修复版本，不能借用暂停续跑入口。
